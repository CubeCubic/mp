Как добавить IP для доступа — найдите в начале app.js этот массив и впишите нужные адреса:

const ALLOWED_DOWNLOAD_IPS = [
  '123.456.789.000',   // ваш IP
  '111.222.333.444',   // ещё один
];

Свой текущий IP можно узнать на api.ipify.org. Чтобы снова заблокировать — просто очистите массив.

## Превью треков при шеринге (кнопка "Share")

GitHub Pages отдаёт статические файлы и не умеет подставлять разные og:title/og:image под разные `?id=` в `track.html`, поэтому для каждого трека заранее генерируется отдельный маленький файл `t/<id>.html` с правильными данными для Facebook/Twitter и мгновенным редиректом на настоящую `track.html?id=...`. Именно на такой `t/<id>.html` теперь ведут все кнопки "Share" — и на карточках, и в шапке (если сейчас играет трек).

Генерирует эти файлы скрипт `scripts/generate-share-pages.js` (тянет треки/альбомы из Firebase и пишет/удаляет файлы в папке `t/`). Запускается он сам, по расписанию, через `.github/workflows/generate-share-pages.yml` (раз в ~20 минут) — коммитит изменения в репозиторий, если появились новые треки или поменялись/удалились старые.

Если после первого добавления GitHub Actions ничего не закоммитил:
- Проверь, что в репозитории включены Actions (Settings → Actions → General).
- Проверь там же, что "Workflow permissions" стоит на "Read and write permissions" — иначе Action не сможет запушить изменения.
- Запусти генерацию вручную: вкладка Actions → "Generate track share pages" → "Run workflow", либо локально: `node scripts/generate-share-pages.js`.
- У GitHub есть особенность: расписание (`schedule`) может не сработать, если в репозитории не было активности (коммитов) больше 60 дней подряд — тогда просто запусти вручную через "Run workflow" один раз, дальше расписание снова оживёт.
